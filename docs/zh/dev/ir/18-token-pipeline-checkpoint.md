# RFC 令牌流水线：有限检查点

本检查点基于 `40f6bca81a169722cc84e4b683bb37cb517d23a0`，实现有限直线
令牌降低，尚未完成五阶段计划或第一个完整里程碑。`ddr_split_k` 仍需
结构化令牌传输。生产 `RealizeSync` 路径不变。

C++ 和 Python 提供 `InsertSync`、恒等 `OptimizeSync` 和有限 `LowerSync`。
降低读取实际令牌定义、使用及命令位置，不重新生成存储最小需求，不依赖
隐藏分析缓存，并保留手写的更强依赖。资源目录及通道着色算法由原路径共享。

三个独立审查分别接受架构、正确性及算法设计。初始基线 89 项通过；较宽
回归门 913 项通过、28 项已有警告；最终重新构建后的定向门 122 项通过，
含 30 项新令牌测试和 C++ 生成。较宽回归门在最后一次仅涉及序列收集的
修正之前运行，最后修正由最终定向门验证。

有限 matmul、累加 matmul 及 Vec 的物理 PTO 输出与直接路径逐字节相同，
分别产生 4/4/0、10/10/0、2/2/1 个 SET/WAIT/屏障。独立解释器比较完整
负载顺序、覆盖、匹配、无环性、消费后重新发布和所选固定图的方向宽度。
最小性不推广到所有令牌扇出实现。

三次交错计时对显示独立令牌阶段有约 2.4–3.8 倍主机开销，这些小用例的
总时间仍低于一毫秒；不声称生产或设备加速。新增工作包括验证及访问导入。
