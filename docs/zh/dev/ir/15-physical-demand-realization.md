# 物理同步实现

共享物理服务降低合格的实际 token 交接和诊断需求计划，不支持任意 token 控制流。
分配、命令调度和物化分开；成功分配将族记录移入不可变 `AssignedSyncPlan`。

每个交接保留匹配的发布/消费 occurrence、原始坐标、活动守卫和方向。逻辑 token 的扇出可以
需要多个物理交接。复用必须有消费先于再发布的因果路径；语句顺序、子区域边界或计数器复位
都不能代替该证据。

有限交接使用有序复用阈值和区间着色；重复族使用充分的循环通道预留及边界路径证明。
未证明重复分配不等于固定协议容量不足。目标资格、保留 ID 和原生宏所有权限制资源池，
调用者只能进一步缩小它。不得增加同步来强制分配成功。

严格直接插入保留现有同流水屏障的顺序条件与硬件豁免。端点守卫在原切点必须就绪；
调度保持有序命令和 ID，守卫共享不授权修改逻辑协议。

`RealizeSync` 只发布完整合格的函数计划。下游 PTOAS autosync 保持开启，跳过有合格显式 flag
的函数并处理委托函数；空或仅屏障的候选委托而不伪造 flag。详见
[生产 pass](../passes/59-realize_sync.md)。

通知入口状态、匹配闭合、返回时载荷完成、物理复用和原生正确性是不同义务。
闭合通知不证明最终异步载荷已在返回前完成。主机验证不能给出一般原生入口/返回保证或设备加速
结论。[架构契约](33-sync-architecture-contracts.md) 记录所有权；
[历史物理检查点](https://github.com/tonibohnlein/pypto/blob/365b803a45072f1c00e8eca5da9942bd9828685f/docs/en/dev/ir/15-physical-demand-realization.md) 保留原推导和固定版本实验。
