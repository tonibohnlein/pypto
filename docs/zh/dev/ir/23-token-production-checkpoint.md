# 生产令牌流水线检查点

五阶段迁移在合格有限、旋转缓冲、边界捕获和嵌套投影范围内完成。
可选 `RealizeSync` 使用共享 `InsertSync → 逻辑令牌 → OptimizeSync → LowerSync`。
`OptimizeSync` 当前仅验证；默认仍委托 PTOAS。旧直接物理化仅保留显式审计入口，
导出或资源拒绝保留原始函数，不用旁路替代令牌语义。

实现版本为 `421b91fa703ce429429529d3aedef2e5742078d4`。完整数据和复现命令见
[英文检查点](../../../en/dev/ir/23-token-production-checkpoint.md)及其 JSON 收据。

## 验证

新的同步专用测试门通过 **1269/1269**，有 32 条既有弃用警告，并非全仓库测试。
覆盖实际保留覆盖边、四类事件查询、存储边界、零次数、重置、原始坐标、序列化、
匹配、因果复用、硬件规则及拒绝回滚。

最终实验对七个代表输入的八次有界执行独立检查旧/新计划，完整负载前提关系双向
相等，没有新增或删除的前提。执行 SET 数量一致：4、10、19、2、18、19、15。
七个输入及五个 Qwen 配置的生产结果与序列化独立阶段相同；**12/12 候选 C++ 输出**
成功生成。Qwen 的独立有界证据复用同配置的 M4 门（layers=2、hidden=512；output
band3、gate/up bands0–3）。这不是新的设备运行。

审计基线只有在既有完整物理证书及非空 SET/WAIT 检查成功后才重建旧包装器的所有权
属性，以进行槽代码生成；并未绕过资源检查。已有逻辑令牌在委托前拒绝，应调用
独立 `LowerSync`。

## 代价和紧凑性

每例有三组交错计时。审计基线包含 Python 接口开销，不是旧二进制生产基线。
新令牌路径编译工作增加，不声称编译或设备加速；独立阶段的包含计时不能加到生产
总时间。英文表保留全部结果。完美嵌套的静态标志对从 6 增至 7，算术从 50 降至 44，
实际执行仍为 15 对且负载顺序相等；其余测量输入的命令/算术数量不变。

嵌套次数从 `(2,3)` 增至 `(10^6,10^6)` 仍保留 7 个族、至多 5 个轴、32 次解析语句访问。
单元素区间可省略轴。独立数学接口项从 1288 增至 6664；这些不是令牌顺序所有者的
统计。源树始终 5 个节点，不展开生产循环。相同负载体的启动范围 1、8、10 对应
1、1、2 个激活情况；不据此声称任意情况数量的常数成本。

Output hidden8192 仍因每激活情况多次访问而拒绝。Gate/up 2048 和 8192 保留
90 个族、200 个轴、90 个 SET/WAIT 站点和 692 个算术操作。改变 hidden 同时改变
输出网格，不能当作纯 K 扫描。

## 保留的界限

任意数据相关令牌控制、非矩形守卫、一般动态嵌套、部分 DMA 同管道机制及缺少资源
证明仍拒绝。六 ID 分配算法、标量屏障禁令和合格累加器规则不变。

论文可据此主张合格访问模型上的精确需求、可序列化的逻辑完成接口及合格物理实现。
逻辑匹配不等于负载完成，物理可行性不等于最小 ID 预算。PTOAS 委托不构成论文的一般
保守分析。原生入口/返回及设备正确性、性能仍是独立义务。

构建使用当前工作树；保持指定的 PTOAS v0.72、Python 3.11 启动器和 Python 3.14.7
扩展环境，不读取陈旧 macOS env.sh。本机检查串行，产物位于 build-py314。
已有设备任务未改动；后续设备任务须显式固定新提交。
