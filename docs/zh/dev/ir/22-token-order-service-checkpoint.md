# 数值事件顺序服务检查点

本检查点基于 `f0ad5a36a`，为嵌套 token 传输准备共享服务。
它不启用嵌套 `LowerSync`，不改变生产调度，也不新增分配器。

## 所有权与正确性

`BuildNumericalMergeOrder` 仅接收精确子区域事件顺序、原始边界端口和显式跨界边。
调用方负责提供原生链连接，并保留后续合并需要的端口。
服务不读取存储访问、不生成冲突，也不执行需求约简。
参考顺序向前的路径通过左子区域、跨界边和右子区域分解；前向与反向数值行组合得到同一闭包。
开始与完成事件保留不同的链。

`QueryNumericalOrder` 使用同步叶查询回调和工作计数器。
回调必须与叶数值行一致，具有自反性和链上的单调性。
端口投影后仍可沿保留的层次结构查询原始内部事件。
现有数学分析继续生成并约简存储跨界边，再把约简结果传给共享服务。
未来 token 调用方必须提供实际 token 边，并单独保存每个通信身份。

## 成本与验证

索引合并核心的工作量为 `O(kP + k²E)`；P 包括被检查但未保留的子端口。
有序容器索引另需 `O(P log P)`，接口构造、叶查询和层次遍历分别计费。
这不是整个编译器的线性复杂度声明。

独立原生测试展开显式事件图并计算闭包，检查 2,000 个生成样例和
1,396,352 个事件查询，包括全部四种事件组合、端口投影和多层合并。
生产回归另行检查存储约简、选择器、物理导出、Qwen 和已有 token 路径。
广泛回归通过 1,119 项测试（28 项已有警告）；格式整理并重新构建后，
针对性回归通过 96 项测试（两项已有警告），原生检查再次通过，仓库检查全部通过。
三类审查者已接受这项准备工作；具体结果和哈希见[回执](../../../en/dev/ir/token-pipeline-m3a.json)。

## 尚未完成的工作

嵌套插入需要按原始调用帧初始化、同时传递、捕获来源并保留精确目标条件。
嵌套降级必须根据实际 token 建立需求族和复用证明。
仿射坐标本身不能证明顺序一致性：仅在首轮存在的路径不能证明所有后续复用。
调用方范围、块条件和生产 token 编排仍待实现。
现有直接生产路径保持可用；没有新增设备验证结论。
