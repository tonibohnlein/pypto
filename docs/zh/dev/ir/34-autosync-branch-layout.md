# Autosync 分支组织和验证

分支分为四个审查单元：Buffer 访问与布局前提、逻辑完成 token IR、集成需求分析与合格物理降低、
以及维护文档。公共流程为 `InsertSync` → `OptimizeSync` → `LowerSync`，由显式启用的
`RealizeSync` 事务性组合。详见[逻辑同步](11-logical-sync.md)、
[有限分析](12-sync-demand-analysis.md)、[逻辑实现](14-logical-demand-realization.md)、
[物理实现](15-physical-demand-realization.md) 和[架构契约](33-sync-architecture-contracts.md)。

## 重构边界

已发布的 `codex/pypto-buffered-intervals` 固定于
`365b803a45072f1c00e8eca5da9942bd9828685f`，保持不变。
新分支 `codex/pypto-autosync-clean` 基于上游 `d0127ff79`，重组净差异，而不重放 14 个开发提交。
四个更新的上游提交无冲突合并，其 CI、A5 VF、非有限常量和描述符 ABI 改动均保留。

未删除生产算法、token 契约、分配策略、物理 ID 分配、用例或独立检查器。
源代码审查确认诊断 API 有测试使用者，不能仅因它是诊断入口就判定为死代码。
前两个包建立前提，第三个包保留耦合入口，避免引入暂时缺少定义的声明。

## 验证

初次重构树构建成功，聚焦测试通过 1,814 项。16 个生成 C++ 与已发布源快照逐字节相同，
235 条有序命令轨迹一致，九个用例通过独立访问、顺序、匹配和物理复用检查。
文档配对、导航、文件头和英文检查通过，审查者已接受完整结果。

包边界经过静态依赖审查；未分别构建每个中间提交，构建和测试覆盖完整树。
后续源代码清理已折入同一组提交：实现提交不包含重复发射器及过时生产包装函数。
其聚焦验证通过 363 项测试和两项计数回归，保持 16 个逐字节相同输出及 235 条轨迹。
