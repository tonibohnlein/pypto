# 运行时有效轴、归约与直接转换

状态：设计与固定原生实现的源码资格审计已获接受，独立构建和测试仍在进行。
本工作扩展 M2 共享操作/元数据契约，供 M3/M4 保守组合消费；未添加后端、分配算法、
私有分支历史、调用次数假设或按内核名称特判。

`PhysicalLogicalVecDescriptor` 只恢复既有描述中的物理形状、布局、原点和步长。
容量投影不是精确有效访问或选择器答案。静态帮助器分别检查原始有效范围；动态
操作通过每次使用前的元数据恢复和 `BufferRuntimeValidAnalysis` 保留实际表达式。

FP32 行 sum/max 与列向量行广播支持运行时有效行及固定、完整、正的源列数。
源/目标有效行必须在使用点相等；列向量具有相同有效行和一列。不会把完整向量
静默缩成部分矩阵。原生操作由正行条件保护，零行不执行它。`0<=r<=M` 仍为操作
输入有效性前提，并非新增的调用者上界证明。

完整容量的连续 FP32 列 `[M,1]` 与行 `[1,M]` 可保留 `[r,1]` 与 `[1,r]` 有效前缀
轴映射。两个原生描述对象分别拥有元数据，指向同一个已证明放置的物理字节区间。
每次使用恢复原始有效轴，既不按指针别名传播元数据，也不支持无地址动态重新解释。
reshape 的实际形状参数还必须与声明的结果一致，字节数相等本身不够。

BF16/FP32 转换共享这些服务，要求同形物理矩阵、固定完整正列、相等实际行、既有
舍入/饱和规则和源/目标不重叠。动态转换使用拥有元数据的原生句柄，不用借用视图
代替缺失的所有权证据。

固定 A2/A3 `pto-isa 5487a6b0` 的 FP32 动态行归约使用通用向量帮助器，不选择整数
标量分支的编号事件。sum 每次重复输出一个标量，max 选择 ONLY_VALUE；输出步长
为一，因此仅写有效前缀，不保证无效尾部为零。显式工作区包围每行中间段和掩码尾部。
运行时行数及归约块步长满足 uint16 编码，元素地址乘积满足 uint32；原资源目录中
保守的整数变体事件预留保持不变。

行广播按 `ceil(r/8)` 组读取列向量，可能包含无效但已分配的填充；物理行数为八的
倍数保证读取仍在分配内。Count/Norm 小行模式及大行分块均位于原有固定 8 KiB
暂存区。大物理行 Norm 模式保留 uint8 重复步长要求，地址乘积满足 uint32。
访问模型保守包围整个分配与暂存，不声称只精确读取有效行。

直接 BF16/FP32 转换的 head/tail 循环使用实际有效行列与物理步长，不选择整数暂存
或事件分支。完整列数为十六的倍数，转换前的原生行步长满足 uint16，元素偏移满足
uint32。上述约束来自指令编码，不是扩大准入上限或基准特例；其他目标仍不可用。

独立前端测试组合动态归约、双向有效轴映射、匹配有效域的标量运算、广播和存储，
覆盖零/一/尾/完整行、选择/跳过、重复与计数重置，以及调用间实际元数据变化。
解释器独立展开原访问字节，单独计入向量舍入读取及暂存，比较完整逻辑 token 与
物理程序的载荷事件序；匹配、无环、六 ID 定向资格及消费先于再次发布分别验证。
动态精确选择器仍不可用，保守前缀结果不构成最小需求保证。

拒绝测试区分元数据不匹配、缺少正行保护、部分列、目标、别名、原生字段溢出、伪造
reshape 形状和无地址元数据所有权。大常量行程只检验表示规模，不展开动态访问。
原 Qwen post-RMSNorm 的完整加部分有效域相加及完整向量配部分矩阵仍是独立契约
义务；本构造不供应无效尾部零值、不假设 `r=M`，也不以保守地址效果修复该问题。
无设备执行或性能结论。

新鲜的原始两层 Qwen prefill 捕获（batch=1、sequence=128、库 `b72c66d9`）在显式
保守前缀策略下产生全部 32 个 C++ 叶子，PyPTO 所有权从上个检查点的 14 个增加到
16 个：新增 `x_gamma` 和 `x_gamma_0`，复用动态 BF16/FP32 转换与广播服务。模型源码
未修改；完整模型尚未全部归 PyPTO 所有，也无设备验证。一次含全部阶段的 6.487 秒
捕获是描述性编译成本，不是最小需求生成时间或加速证据。

运行时家族的 60 项测试通过，包含 40 次轴/归约、32 次转换以及保留的 24 次广播
有界执行。编码拒绝使用互不重叠的合成窗口并匹配原生字段诊断，不能由别名或容量
拒绝冒充编码验证。最终集成检查与提交门记录于英文配套 JSON 回执。
