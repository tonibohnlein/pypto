# 直接构造共享同步控制

本检查点基于已审查的分支命令序列共享实现。起点是
`4f5fdfeada1085841de6cb5bfd7637d391a9663e` 加上工作区修改；
`build-py314/direct-control/baseline/source.json` 固定了这些文件。
单独的提交号不足以标识基线。[机器可读记录](../../../en/dev/ir/direct-sync-control.json)
包含源码、工具、命令与结果。

## 契约与所有权

`LowerSync` 消费实际 SSA token 的使用。作用域解析器在把坐标展平为分配坐标之前，
保留不可变的端点区间（endpoint intervals）。每个域引用共享的原始帧上下文：
函数、调用分支、区域和原始循环。半开区间保留源坐标替换与目标守卫。
能力不可用不等于空区间。

分配器保留这些句柄，只生成现有的 ID 分配。降低检查所有者、分支、区域和帧身份。
数学诊断入口在兼容边界解码为相同的端点表示。这并不允许数学分析旁路覆盖实际 token 使用。

在每个原始负载插入点，物理降低构造有序命令描述符（command descriptors），
其中包含已分配的动作、方向、ID 和执行域。插入点清单拥有位置及前后顺序。
相邻守卫共享、分支前后缀共享、调度选择与大小计算都在描述符上完成；
只有选中的森林才物化为语句。旧的生产语句森林调度路径已删除。
测试辅助入口把纯命令语句导入同一个调度器。

每个保留域缓存端点谓词，仅使用不可变的原始循环边界简化，不引入分支局部事实。
现有的最终作用域局部标量值物化器保持独立，且不把值移出未执行的分支。
分配算法、逻辑协议、硬件豁免、同步位置和负载指令均未改变。

## 精确并集与成本证书

两个不相交调用区间上的相同完整命令序列可以共享一个命令体。例如：

```text
if block <= 4: S
if block >= 19: S
```

变为：

```text
if (block <= 4) or (block >= 19): S
```

编号 5 到 18 仍然不执行任何命令。整个有序序列必须一致，包括 ID、方向、守卫的 SSA 身份
以及重复命令。该操作不合并仅部分相同的符号族或不同协议。

共享必须在静态命令、守卫和表达式大小上取得 Pareto 改善，并通过每个插入点的最坏控制成本
证书。比较、立即求值的布尔操作和条件分支分别计数；检查使用精确区间真值分区，
区分执行相同命令体与执行空命令体的情况。标量 `And`/`Or` 的两个操作数都计入，
不是宿主语言短路求值估计。

只有当内部工作的可取值域与调用区间无关时，才能抵消其不变成本。
初始充分条件允许字面常量边界、正步长的原始循环 IV 和常量，且中间没有条件控制。
非字面边界的嵌套循环清除较早的 IV 证据；同一插入点的别名访问取证据交集。
未知 SSA 值或相关控制保留原方案。这是逐插入点界，不是整个内核的精确运行时间界；
单个分支的成本可能变化。当前并集子类恰好包含两个非空残余序列。
对三个完整覆盖执行域的 `A/B/A` 分支，可先剥离相同的有序前缀和后缀，要求中间残余为空。
完整内部工作必须满足相同的取值域独立性证书；分派成本与实际选中的原方案比较，
最终大小检查包含重新接回的前后缀。其他并集保留现有树。

## 原始坐标边界规范化

对原始循环 `i = 0 .. 256 step 64`，最后一次访问是 `i == 192`。
降低可直接生成该比较，而不生成 `(i/64) == 3`；非首次区间类似地使用
`i >= 64`，而不是 `(i/64) >= 1`。

证明要求相同原始循环和帧、字面常量起点与正步长、有效访问数字、可表示的阈值和最后 IV，
以及规范化减法跨度 `(count-1)*step <= INT64_MAX`。检查在 `__int128` 中完成。
不能整除的停止值使用实际格点，而非 `stop-step`。空帧没有端点；单次访问域不删除重复命令。
未知或符号起点保留原规范化表达式。负起点仍在既有导入契约之外；
本检查既不扩大准入范围，也不认可溢出运算。

符号族统一、阶段重组和循环拆分仍是独立工作。本检查点不克隆负载，也不推断新周期。

## 测量范围

记录分别报告静态命令、分支、守卫表达式出现次数、C++ 字节数、有界执行命令、
标量比较、布尔操作和算术操作。表达式出现次数不是原生指令数。
独立顺序检查检查生成的 C++，并显式报告不支持的 oracle 情况。
精确轨迹等价包括负载插入点、方向、ID、重数和顺序，因而保留已检查的先决关系；
代码缩小不以减少通信或增加负载顺序为代价。

构造计数区分首次请求守卫时访问的端点区间、构造的谓词根、描述符分配（包括被拒绝的候选），
以及最终选定森林实际构造的语句。`materialized_control_statements` 包含序列包装，
但不包含现有最终 CSE 重构或原始负载树重构。解析器映射键复制与算术简化器内部工作不在
这些计数中。生产时间与诊断构造清单分开报告。单次计时不证明加速。

## 结果

28 个测试输入的 477 条有界有序负载/命令轨迹与起点完全一致；前后版本均完成全部
28 个输入的 C++ 生成。完整同步测试门通过 **1,577 项测试**（37 条警告）。
独立 C++ 顺序检查在十个测试输入上完成 15 项检查，六项比较仍明确标记为不支持。
记录区分功能构建与最后仅格式变更后的重新构建和集中复查。

| 输入 | SET/WAIT 静态位置，之前 → 之后 | IR 分支 | 守卫表达式出现次数 | C++ 字节 |
| ---- | ------------------------------ | ------- | ------------------ | -------- |
| Gate/up H=5120，band 2 | 68/68 → 63/64 | 168 → 147 | 640 → 485 | 42,186 → 39,004 |
| Gate/up H=512，band 2 | 52/52 → 47/48 | 96 → 83 | 352 → 285 | 31,975 → 30,453 |
| Output H=5120 | 17/17 → 17/17 | 27 → 27 | 113 → 85 | 17,599 → 17,307 |
| 嵌套输入 | 7/7 → 7/7 | 10 → 10 | 66 → 30 | 6,943 → 6,695 |

SET/WAIT 静态位置数不相等不代表通知不匹配；每次检查的执行均保持先前的精确命令序列。
原始 Qwen 嵌套重复现在成为精确并集守卫后的共享残余命令体。

大规模 gate/up 的两个层、全部 24 个块累计结果如下：

| 建模的标量工作 | 之前 | 之后 |
| -------------- | ---- | ---- |
| 条件决策 | 122,692 | 117,858 |
| 比较 | 125,412 | 127,412 |
| 布尔操作 | 2,720 | 9,554 |
| 算术操作 | 39,392 | 2,368 |

并集决策增加了一部分比较与布尔操作；仅计分支减少会隐藏这种取舍。
合计建模原语工作从 290,216 降至 257,192（11.4%），477 次测量执行中没有一次增加合计值。
该有限验证不构成统一运行时间定理或设备加速证明，也没有用硬件模型把比较与除法视为相同成本。

旋转访问次数增加到 1,000,000 时仍保留 9/9 静态命令和 20 个分支；嵌套次数达到
(1,000,000,1,000,000) 时仍保留 7/7、十个分支和 30 次守卫表达式访问。
调度器不随参数大小展开访问；不同分支划分仍可能需要不同的真实命令族。

| 已建立的结果 | 剩余限制 | 对论文的影响 |
| ------------ | -------- | ------------ |
| 共享控制构造保留精确有序轨迹 | 已资格化的原始插入点、帧域和物理方案 | 控制表示可独立于最小需求分析缩小 |
| 有界访问/顺序、匹配和复用检查通过 | 宿主模型与既有原生前提 | 缩小代码不必增加负载顺序 |
| 原始 IV 格点比较删除商计算 | 已证明静态格点；符号起点保持原形式 | 紧凑匹配公式也需要有资格依据的经济降低 |
| 没有新增分析器、分配器或生产 AST 后备调度 | 符号族统一与阶段重组保持独立 | 数学紧凑性本身不约束全部同步代码 |
