# 自动同步审查修复

## R1：有界发现与独立的物理输出

闭合前缀发现对共享表达式节点只访问一次，同时保留语句出现次数。
令牌使用摘要按表达式身份缓存，并在每个实际使用处计数。
仅删除已证明为空的完成事实及其纯 SSA 别名；不支持的令牌框架在修改前拒绝。

每次逻辑到物理降低成功后，检查不存在逻辑操作、SyncTokenType 值、
元组成员和函数签名。运行时 TaskId 保持独立。
无效编译器输出在发布调用所有权之前触发内部错误。

新的主机验证覆盖 28 层共享 join 回归、八种 completed 别名情况
（有载荷或仅命令、启用或禁用优化、序列化），以及既有 carry/capture 和子区域测试。
首批五模块修复测试 166 项通过。接口测试 154 项通过，并发现此前暂停且尚未资格确认的
active-domain 测试包存在六个解析失败；单独保留这些失败记录，不作为里程碑通过证据。

这些检查建立受支持主机模型的行为，不证明原生或设备正确性。
逻辑协议、可用 ID 池和分配算法保持不变。

## R2：独立于策略的原生工作区合法性

所选原生操作提供共享的操作数与工作区分离检查。精确访问恢复使用已有物理边界；
保守分析与实际令牌资源资格确认使用索引化的局部放置信息。不可用边界保持不可用。
操作之间的同步不能修复单条原生指令内部的重叠。

每个相关显式操作数必须与同内存空间中的隐式工作区分离。半开区间的相等边界合法；
发布边界前检查算术。别名保留分配身份。运行时子视图继承 Buffer IR 中窗口位于源分配
之内的契约（[类型](02-types.md)）；父分配包围不是精确选择器。
槽索引需要独立证据：当前适配器接受范围内的静态索引，工作区检查拒绝不支持的动态索引。
缺少分配来源的借用操作数可能已经被 Buffer IR 验证拒绝，与同步策略检查独立。

公共回归覆盖精确和保守分析、插入、实际闭合令牌降低及事务式实现，包含读写操作数、
视图别名、工作区边界、不可用放置与槽。隐式工作区效果仍参与操作间冲突分析。

## R3：动态别名提升后的静态行描述符

静态稠密行主序的行操作输入和输出现在使用已有静态描述符窗口桥接。
先执行通常的逐使用点元数据恢复。即使另一别名使共享分配描述符变成运行时元数据，
每个使用点仍保留原有效范围与物理行距。列主序载体保留已有独立类型根描述符；
动态操作数仍受完整列契约和原有守卫约束。

十六项聚焦测试覆盖 PYPTO、DSA_RP、PTOAS 放置，部分与完整列，求和/减法与最大值/乘法，
行调用后再次使用别名、零与较短元数据、禁用 Buffer 的对照以及未证明元数据拒绝。
检查实际行调用描述符及独立 Torch 数值。最终描述符、工作区和元数据组合测试 134 项通过。
载荷算术、守卫、物理布局与同步策略保持不变。

## R4：嵌套发布调度与新回归门

深度扫描把另一种表示扩展定位到发布排名。通用语法按所有原始族边界切分每层，
规范进位族可能因此产生每次动态发布一个片段。可选生产者现在识别同一原始叶中
单一源/消费者站点对的完整混合进制后继分区。每个非单例维度的进位类恰好出现一次，
检查原框架、所有者、域、单位格点步长、基点和乘积溢出。互斥类覆盖除最后一次外的
所有源序号；每个原始标签的仿射排名等于原源序号，保留标签与匹配映射。

接受前，由已有实际令牌顺序服务对整个类证明目标消费先于同次访问中下一发布的源载荷。
这比所需 WAIT 到 SET 路径更强。相邻复用及匹配 SET 到 WAIT 路径也支持任意正预算。
形状或证明失败保留原语法；分配器、可用资源、协议与逻辑令牌保持不变。
该改进有明确适用范围，不解决任意族并集。F 个类和 D 个框架的结构及排名构造为 O(FD)，
顺序查询成本另计。

重新构建并固定二进制的单次主机测量：深度 8 时片段 255→8，SET 260→13，
守卫 2007→88，物理准备 0.10430→0.00518 秒；深度 12 时片段 4095→12，
SET 4100→17，守卫 32711→180，时间 2.14734→0.00976 秒。
候选深度 16 为 16 片段、21 SET、304 守卫和 0.01616 秒，未尝试该深度的基线。

沿用每阶段 12 秒看门狗；这些是主机构造观察，不是设备加速。
独立有界检查比较实际排名/标签、令牌和标志载荷顺序、覆盖、匹配、无环及复用。
重复使用、活动域空洞、外来所有者与缺少复用路径保持保守行为。
操作测试继续拒绝静态空域，并在函数/使用点要求运行时元数据证据。

最终隔离修复回归门在 397.39 秒内通过 2,910 次测试执行，零失败，四项已有弃用警告。
两个显式模块与基础清单重复，因此次数不是独立测试数。
[回执](../../../en/dev/ir/42-autosync-review-repairs.json) 保留命令、二进制/源码固定信息和原始日志哈希。
R1–R4 修复资格确认不代表原 M1–M6 覆盖目标完成。
