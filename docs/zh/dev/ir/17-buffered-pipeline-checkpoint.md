# 紧凑缓冲流水线实现

英文文档为准：[实现契约](../../../en/dev/ir/17-buffered-pipeline-checkpoint.md)。
本工作按五个阶段实施，每阶段通过独立审查后才进入下一阶段。

1. 使用已有 MultiBufferType 增加分配、槽选择操作和 Tile→Buffer 转换；保留物理地址、别名和原始下标。
2. 公共步长周期访问的生成、约简及查询；不展开槽或循环次数。
3. 数值链接口与共享区域组合；独立验证实际覆盖边及重置边界。
4. 常驻与流式存储边界；区分精确成员关系、无访问与不可用。
5. 使用已有物理实现验证匹配、因果复用、六 ID 分配和 C++ 生成。

第 1 阶段的 buffer.alloc_multi(valid_extents, [effective_base]) 拥有完整槽组；
buffer.slot(group, index) 返回别名句柄，不创建新分配或负载读写。
循环 iv=start+i*step 的选择表达式 (s*iv+c)%b 仅在原始整数中间值已证明
非负且不溢出时，归一化为 (first+i*stride)%b。物理地址为 a+slot*w+槽内偏移。
相同物理布局共享身份，不兼容重叠、部分槽视图、未证明的参数相位保持不可用。
只读 testing.describe_placed_sync_input 仅报告访问证据，不声称已完成需求分析。

保留现有硬件例外、分配算法与默认调度。PTOAS 委托不是论文保守令牌算法。
原始 Qwen 调用方范围缺失继续拒绝。不进行设备验证。

当前阶段仍在实施，结果见英文目录的机器可读 receipt。

原生多槽降低会按目标内存对齐要求调整槽步距。因此导入与发射仅接受描述符字节步距
和固定基址均已对齐的多槽族，不会忽略填充。单槽组使用普通原生分配。
原生槽数量限制与数值 IR 的表达能力分别报告。

当前别名恢复可能对 V 个静态视图/分配逐一扫描 S 个存储描述，成本为 O(V*S)。
本阶段不声称整个访问恢复过程满足规范化输入识别定理的界。
使用的已有规划器对齐要求是原生对齐的充分条件，可能比 PTOAS 最小要求更强。

架构/性能与正确性独立审查均已接受；串行回归门禁 **1,599 项通过**，
用时 88.37 秒。覆盖普通 Buffer 选择、显式降低、序列化、物理访问、
别名/几何拒绝以及 PTOAS C++ 生成。收据固定了未提交源文件和二进制哈希。
五个限定阶段均已实现并通过独立评审。没有设备验证。

## 第二阶段：旋转生成器与数值查询

每个已验证物理族保留公共步长 `s`、槽数 `b` 和精确静态访问片段。
令 `h=gcd(s,b)`、`R=b/h`；不同余数轨道不重叠。在轨道内按模相位及
体内位置排序，通过严格前后写者扫描构造 RAW/WAR/WAW 生成器，并在归约前
去重端点与距离。RMW 参与写者链。不展开槽、周期或循环访问。

商图分别保留开始与完成事件、权重为一的原生回绕边和带访问距离的需求边。
每条管线通过多源最短路径得到 `beta_p(v)=h_p-D_p(v)`；源秩 `r` 在距离
`d` 后可达当且仅当 `h_p*d+beta_p(v)>=r`。开始源与完成源分别建立索引，
支持四种事件查询；同一事件被严格查询排除。带检查的宽整数保留过大的阈值，
不把它伪装为不可达。归约保留两个不同入边身份的最大前缀值（包括平局），
排除待测边后判断替代路径。引用顺序向前排除了通过待测边自证删除的非正环；
存在端点之间的路径也不会越出有限调用，所以尾部只需裁剪端点。

`boundary_slot` 求模进程与仿射成员关系，保留首末写者、各管线只读前缀/后缀、
RMW 身份和原始访问坐标。省略多槽坐标是接口不可用；已覆盖但未访问的槽返回
可用的空摘要。移动只读 GM 仍有精确点成员关系。

归一化片段之后的提取为 `O(A log(A+1))` 比较与线性扫描，索引保留 `O(km)`
项。普通静态矩形归一化最坏可能检查 `O(A^3)` 个切分与访问组合，单独计入
`atom_tests`；整槽只有一个槽内原子。访问和别名恢复另计。超硬件容量数值描述
仅用于表示规模测试，不代表可运行的物理分配。

此阶段只支持单个不变周期区域。启动相关效果、受保护累加器变换、共享写域的
移动访问、多区域槽组合和新的可执行端点仍明确拒绝；导出失败不修改已保留数学结果。

第二阶段已验收：**1,649 项测试通过**（87.57 秒），架构/算法和正确性独立审查均接受。

## 第三阶段：数值组合与共享复位重复

层次结构引用既有叶子数学结果。精确存储/原生端口分别组成开始与完成链，
单调扫描建立前后阈值。合并生成写者/读者桥接和原生边，按完整事件身份去重，
通过含等值位置的秩桶与两个不同见证归约跨界需求。父行合并子内路径和一次跨界
路径；查询使用后缀最小值和前缀最大值索引，不构造全对矩阵或重建图搜索。

子区域必须是原始顺序的连续区间，跨界路径恰好使用一个跨界边，内部覆盖边
因而保持有效。空子区域传递存储与原生前沿，不意味着完成、通知消费或 ID 复位。

不变物理效果、内部模槽选择的数值完美循环嵌套现在保留一个内层调用。
二进制平方共享不可变节点，并为每次使用平移身份。公开三元组仍是原始混合基数
出现坐标，而地址公式使用局部内层访问，因此每次外层调用都会复位槽相位。
叶子需求仅在其作用域内实例化，复位义务由节点跨界边保留。外层相关几何、启动
谓词和不支持的累加器前提不会被推断出来。

有预算的研究接口只展开已保留需求供独立有限 oracle 比较，不重新分析。
层次结果的扁平跨界清单标为 `None`，不伪装成空集合。物理导出仍等待第五阶段。

完整接口枚举每个访问实际覆盖的槽，最多 `min(inner_count, orbit_period)`，
以及静态槽内原子；这是单独计费的接口输出成本，不沿用第二阶段的槽数无关界。
不构造银行联合周期。全局只读物理域无需存储桥接，但仍保留点选择器。
索引内核为 `O(kP+k²r)`；当前适配器另外保存/检查 `O(kS)` 摘要并使用有序集合、
映射与端点查找，额外包含 `O(kS log(kS+1)+r log(P+1)+P log(P+1))` 工作。
计数器分别记录访问、槽、桥接候选和端口归一化。既有无旋转累加器路径保持不变。

固定三个静态站点和三个槽时，内层次数从 4 到一百万、外层七次，接口保持
2,240 项、四个合并节点。外层从两次到一百万次，仍只分析三个站点，节点从一个
增长至 25 个（最大 11,648 项）。这是受支持复位体的共享定义增长证据，
不是任意 Qwen 嵌套或物理标志可行性证明。

阶段 3 已接受：**1,712 项测试通过**（87.70 秒），架构/算法与正确性独立评审均已接受。

## 阶段 4：限定作用域的流式存储所有权

实现前，两位独立评审接受了以下充分构造。对于经过别名资格检查的同一物理存储域，
所有建模访问必须具有相同的平移向量。包括读取和重叠写入在内的所有相对矩形的并集，
必须在至少一个物理上单射的坐标轴中落入相邻平移间隔内。这证明局部访问轮次之间
存储不相交。不绕回的写者扫描保留轮次内所有 RAW、WAR 和 WAW 生成边；只省去
已证明不存在的该域跨轮次存储冲突。原生顺序和其他域的生成边保持不变。

证书属于原始区域及其调用坐标框架。精确点成员关系以及首末写者和读者仍使用原始
仿射访问。覆盖域内的填充和空洞才可返回确实不存在；不支持的域仍返回不可用。

仅当该域的所有访问均属于一个不重复调用的子区域时，父区域才可省去其跨界端口
的物化。其他子区域的读取和写入都会使该捷径失效。重置流式输出地址的外层重复
不能继承内层所有权证明；初始适配器明确拒绝，而不省略重置冲突或展开循环嵌套。
驻留存储和局部旋转存储仍使用已接受的数值合并。

这是论文流式存储前提的受限实现，不是一般嵌套输出组合的保证。已有布局和别名
资格是前提；不同张量名称不能证明物理不相交。不推断新的调用者范围、原生足迹、
分配策略或调用完成语义。

阶段 4 已接受：**1,758 项测试通过**（91.22 秒），两位独立评审均接受。流式轮数 7、1,000 和 1,000,000 均保留 2,128 个接口条目；输出域使用精确仿射成员查询，不逐轮枚举。

## 阶段 5：合格的物理端点适配器

已有分配器改为使用精确 `Threshold(C_target,I_source)` 查询，而不是索引稠密事件
距离表。通道宽度界、着色、方向资源池、原生保留资源和同流水线插入检查均不变。
需求位移为 `d` 时，满足 `q >= d + threshold` 的重用间隔 `q` 是充分的。所有见证边
均沿参考顺序向前，因此两个存在端点之间的路径不会离开其有限调用区间。适配器
在宽整数相加前按族大小裁剪；不可达不被解释为零阈值。

平坦数值层次按原始坐标导出保留的跨界需求，不展开周期族。内部源或消费者位置
使用精确出现范围保护。导出先检查所有共享使用作用域，再验证端点范围和顺序。
需要重复作用域族的重置重复仍不可用；拒绝保留数学结果及事务式委托。这与物理
容量拒绝是不同情况。

专用物理路径不要求实现任意前端令牌降低。超出已有契约的位移令牌传递仍是独立
的不可用能力。匹配、新鲜入口和通知闭合出口在已有命令模型下检查；通知闭合
不证明返回时原生载荷已完成。原生槽资格和 C++ 生成与分析和标志分配分别报告，
不意味着设备验证。

阶段 5 已接受：**1,796 项测试通过**（94.44 秒），包括 **38 项物理同步专项测试及
四个 PTOAS C++ 生成用例**。架构/算法和正确性评审均接受。没有设备测试。

### 测量范围与剩余义务

流式示例的轮数为 7、1,000 和 1,000,000 时，均保留三个需求族并生成 **9 个 SET /
9 个 WAIT 静态站点、零屏障、76 个算术操作**。包含实际驻留读者的前导/流/尾部
变体保留六个族，生成 **12 个 SET / 12 个 WAIT、零屏障、97 个算术操作**。
代码字节长度随常数字面量位数变化，但上述结构大小不变。在六 ID 限制下，有界
执行每个方向最多使用三个 ID；独立有限宽度检查一致，不代表一般最小分配保证。

七轮流式执行有 21 个载荷、18 次发布和 18 次消费，九条因果重用路径且无额外
载荷顺序对。驻留读者变体有 24 个载荷、21 次发布和 21 次消费、十条因果重用
路径且无额外顺序对。原始槽选择、实际命令和端点身份独立于编译器需求族及
分配清单解释。

单次主机测量中，流式分析约 0.32–0.38 毫秒，驻留读者变体约 0.68–0.76 毫秒。
物理准备、分配和发射合计约 0.05–0.14 毫秒。普通生产路径计时已包含分析，
不可与分阶段时间相加。这些是描述性数据，不是加速对比；原生 C++ 成功独立报告。

仅写者前导仍是明确拒绝案例：再次覆盖其局部存储需要同 DMA 流水线需求，当前
物理发射器未限定该屏障机制。另一个驻留读者夹具包含实际向量操作，能通过跨
流水线需求实现。没有给原始案例添加载荷或修改硬件规则。

| 论文构造 | 已建立证据 | 剩余边界 |
| -------- | ---------- | -------- |
| 公共步长旋转需求 | 所选模型精确覆盖、四类事件查询和模选择器；不展开轮数或联合周期 | 一般别名/布局恢复及启动相关效果 |

### M1：精确区间证据

`SyncAccess::physical_interval` 是规范槽内可选的半开字节区间。
Vec 字节域沿用其规范物理坐标；读写模式、槽选择与原始访问坐标仍单独保存。
导入器认可完整分形块、连续的行主序或列主序矩形，以及已恢复的精确字节区间。
部分分形块、不连续矩形、移动或参数相关访问及保守包围范围保留原始效果，但不获得区间证书。
证据不可用不代表访问不存在。本阶段不修改需求、组合、端点或分配算法。

区间检查只遍历已提供的静态访问。现有 Vec 导入仍可能逐行恢复带步长的视图，
这些区间保持独立，不填充间隙。因此本阶段不声称访问恢复与行数无关，
也不声称已实现论文的完整区间列表识别器。原生访存资格仍由现有指令契约负责。

运行 `python -m tests.ut.ir.transforms.qualify_buffered_intervals --output
build-py314/interval-m1-baseline.json` 可记录源文件及二进制哈希、检查工作量、
保留需求、物理实现结果及成功时的物理 IR 哈希。五个基准环形案例仍因既有同流水线机制限制而拒绝物理实现，这不代表容量不足。单次时间仅用于描述，不作为加速证据。
首次测试误用了旧 PTOAS 启动器，四个 C++ 失败均为环境问题；后续测试使用
固定的 PTOAS v0.72 与兼容的 Python，没有为此改变测试预期或编译器语义。
