# 逻辑同步阶段（实验性）

`insert_sync`、`optimize_sync` 和 `lower_sync` 将最小需求分析、逻辑完成令牌
（completion token）和物理事件分配分开。它们在物理地址分配及 Buffer 降低后
显式调用，不改变默认编译流程。

```python
from pypto import passes

with passes.PassContext([], autosync_disjoint_gm=True):
    logical = passes.insert_sync()(placed_program)
    logical = passes.optimize_sync()(logical)
    physical = passes.lower_sync()(logical)
```

`autosync_disjoint_gm=True` 是调用者提供的不同 GM 参数分配互不重叠的契约。
`InsertSync` 复用现有访问导入器、最小需求分析及原始坐标令牌导出。
现支持单区域旋转槽流的常量距离历史；有限数值跨区域导出使用 occurrence capture；满足条件的常量嵌套区域也支持逻辑插入，
并可通过下述作用域数值证书限定物理降低。

## OptimizeSync

`OptimizeSync` 验证令牌模式、执行归属和词法 SSA 使用。它简化含已完成或相同
操作数的 join 绑定，删除等待已知已完成令牌的操作及冗余等待，再删除未使用的
record、completed、join 绑定及令牌别名。仍在使用的 record 保留原有捕获位置。
join 简化和活性分析分别按有向无环图（DAG）的不同节点和边遍历共享表达式。

`LowerSync` 也可直接接收格式正确的逻辑 IR。依赖覆盖和物理可行性需要单独证明。

## LowerSync

在默认的逐内核模式下，若令牌程序仅生成屏障，`LowerSync` 会在原等待位置保留这些屏障，并继续启用下游 PTOAS 同步。调用者可以通过同一流水线上的等待来约束独立操作的执行顺序。

`LowerSync` 首先支持直线有限令牌程序：record、completed、join 和 wait。
它解释实际令牌定义及使用，不重新分析存储来替换手写依赖。记录包含该管线
此前导入的等待。令牌不消耗，多次使用必须分别建立匹配的物理交接。
物理 ID 复用要求证明先前消费到后续发布的因果路径。它复用现有资源目录、
原生保留 ID 及通道着色算法。控制流或同管线放置证明不足时明确拒绝，不能
把这些拒绝视为物理容量不足。

有限直线程序中，每条管线的等待构成有序链。分析为每个事件保留各管线
可达的最大等待序号，并分别传播开始、完成和等待状态。记录合并完成状态
及此前导入的等待。同管线记录的前缀单调，因此 join 等于最新前缀。
只有前一消费的序号可达后一发布时才复用 ID。这为现有生命周期着色算法
提供有序后缀关系；最小性仅针对所选逐使用交接方案，不针对所有令牌实现。

共享表达式按不同节点缓存，嵌套语句序列只收集一次。降低使用独立的负载限定入口
（payload qualification），与插入共享描述符、坐标、控制流、管线及原生资源检查，
但不构建依赖访问足迹、GM 别名划分、物理区间导出或存储启动摘要。
未使用的标量形参不要求范围证明，未使用的张量形参不要求访问模型的几何限定。
原生布局、物理放置、提取及算术限定仍然保留；这些检查实际使用的坐标仍须具有
当前调用者证据。共享限定的成本单独计入；访问恢复属于插入阶段。
插入和降低分别从当前 Program 收集调用者参数及逻辑块范围证据。

在默认的逐内核模式下，独立调用 `LowerSync` 会保留输入令牌程序指定的同管线屏障，
包括调用者通过 `InsertSync` 生成的屏障。PTOAS 可以继续为其余存储冲突添加同步。
Default 流程只调用一次 `RealizeSync`。它使用相同的令牌优化和物理降低实现，并保有
原始的已分配内核。当自动方案仅包含局部屏障时，它将原始内核交给 PTOAS 插入同步。

结构化降低现在支持规范的常量距离循环：记录紧随原始负载（或完整初始化/
累加分支），等待位于目标负载之前。循环携带值必须从 completed 开始，且
每次无条件同时移位。距离 d 的守卫为 `iv > start + (d-1)*step`；三访问历史
yield `[current, previous_1, previous_2]`。解析按变量身份沿历史方程查找当前
记录，拒绝循环或外部调用历史。只有第一历史输出选择最后源访问；非空旧
结果不能冒充最终边界。进入另一个循环时使用精确原始坐标相等守卫。零次循环输出仍为
completed。原始起点、正步长、类型及计数由既有导入器验证。

实际令牌使用逐一成为交接族，不重新提取存储覆盖边。周期前沿由这些边
构造，既有分配器和发射器复用。消费负载完成到下一发布负载开始的路径
提供充分复用证明；此路径不能证明最少 ID。累加器存储转发不会被提升为
完成到开始的事件顺序。

单区间不构造边界图；多区间共享既有首/末端口图，其构造对端口数可能是
二次的，跨区间查询为 `O(P+E)` 图遍历加子查询。周期核心成本为
`O(k(m+u) log(m+u))`，不枚举循环次数。未经作用域证书限定的嵌套令牌、任意结构化 join、非空
入口事实、循环历史、非空旧结果跨界及非规范守卫仍明确拒绝。

标量历史大小 H 是各源最大活动距离之和。插入产生 O(H) 个携带/结果/yield
节点，无活动使用的历史不构造。遍历为 `O((N+F+H) log(N+F+H))`；
解析迭代执行并缓存，不消耗与历史深度成比例的调用栈。固定距离时表示不随
循环次数增长，但不声称对二进制编码周期紧凑。

完整降低并存在 SET/WAIT 后，复用既有物理所有权属性告知 Buffer 代码生成。
该属性表示所给令牌协议的所有权，不证明手写令牌覆盖所有存储需求。空计划
不伪造标记，委托槽选择及原生多缓冲区大小限制保持不变。

`realize_sync()` 已迁移为三个共享阶段的事务式
协调器，保持原有启用开关及整核 PTOAS 委托。逻辑匹配和物理复用不证明
异步负载在函数返回时已完成；原生语义和设备验证仍是独立义务。

完整的当前支持范围见[英文契约](../../../en/dev/passes/60-logical_sync_pipeline.md)。

## 数值出现捕获（occurrence capture）

内部源访问 v 用一个 completed 初始化的携带值保存：在
`iv == start + v*step` 时选择当前记录，否则保留同一携带值，最终循环结果
即所选完成事实。每个源出现仅保留一个捕获，不构造从 v 到循环末尾的完整历史。
多个消费者共享捕获状态，但物理交接仍逐使用分开。

降低检查纯令牌 yield 分支、同一携带值、管线、调用与原始坐标。捕获只能通过
循环结果使用；中间状态不可导出。证明未执行的出现输出 completed，不能把
缺失存储导出当作空访问。消费者 w 使用 `iv == start + w*step`。

所有实际跨越端点在构造子区域顺序链接前注册为边界端口。连续且参考向前的
区域路径由内部链接、跨越及原生边界组成，不能离开子区域后再返回。状态大小
为 `O(H+B)`（历史 H、捕获 B）；端口链接仍按扩大的端口数计二次成本。导出
可能枚举槽或行，不声称任意接口都紧凑。没有新增令牌操作或分配算法。

## 嵌套作用域的逻辑插入

原始区域树可通过已有笛卡尔需求族进行逻辑插入。
端点保留原始循环身份和混合基数坐标；变化轴必须是共同的外层前缀，步幅与范围精确匹配。
当前支持共同变化轴上的相邻访问连接，不支持更长距离或没有外层连接的固定坐标差异。

来源完成事实逐层退出内层循环：末次访问直接 yield，内部指定访问使用纯 token 条件选择。
每层 carry 在其实际调用入口初始化为 completed。
相邻外层连接再把选定事实传到下一次外层访问，因此内层计数器可以重置。
消费者使用精确的原始笛卡尔条件，记录仍位于完整负载宏之后。
共享的是不可消费的完成事实，不是物理 flag 身份。

F 个需求族、D 层循环新增 `O(FD)` 状态和条件节点，不展开行数或循环次数。
上游导出成本单独计算；动态起点仍显式拒绝，并保留数学结果。
逻辑插入本身不证明物理复用；下述独立作用域数值证书限定嵌套 `LowerSync`。

[作用域插入回执](https://github.com/tonibohnlein/pypto/blob/365b803a45072f1c00e8eca5da9942bd9828685f/docs/en/dev/ir/token-pipeline-m3b.json)记录了 29 项针对性检查、
1,148 项广泛回归及重新构建后的 150 项 token 回归。
行数或访问次数增至一百万时，测试的嵌套集体填充仍只有两个 record、三个 wait 和四个 carry。
数值摘要仍需对数规模的重复合并。单次主机时间仅作描述，不构成加速结论。

## 作用域令牌使用解释检查点

诊断接口 `testing.inspect_scoped_token_families` 不假设 GM 参数不相交，
验证逻辑 SSA，移除已限定的纯令牌结构，并通过当前负载限定保留
原始载荷与循环坐标。它解释实际 SSA 使用，不重新生成存储需求，也不分配物理 ID。

令牌模式的有效域恰好表示非 completed 的执行域。completed 初始化、同时更新的
循环携带值和保留自身携带值的纯捕获建立这个不变量。因此，与 WAIT 条件取交集
只会消去等待 completed 的使用。条件必须是活动原始坐标上的精确矩形区间。
重复 WAIT 保持独立交接；无法表示为公共前缀单射族的扇出、中间捕获使用及偏离
合法插入位置的命令仍被拒绝。

一元方程解析按每次使用的精确消费者域迭代执行。捕获并保持语义不能只按令牌身份缓存。
令 E 为实际检查的方程步骤数，D 为坐标帧深度，模式处理为 `O(ED)`，另计索引和域查询。
U 次使用、T 个方程可导致 E 达到 `UT`。可选族规范化单独统计候选比较，组内候选可能
为二次规模。守卫成本按每个条件计入，包括共享守卫的重复访问和嵌套域映射复制。
不展开访问次数；导入、验证和物理复用证明的成本分别计算。

解析成功不证明平移不变的重复顺序或物理复用。该解释检查点本身不启用嵌套 LowerSync；后续数值顺序证书提供单独的物理限定。
独立测试将展开后的实际使用多重集与 SSA 执行逐一比较，覆盖修改后的捕获、
缩小或移除的条件、completed 入口、重复 WAIT、序列化和计数器复位。
详见[机器可读记录](https://github.com/tonibohnlein/pypto/blob/365b803a45072f1c00e8eca5da9942bd9828685f/docs/en/dev/ir/token-pipeline-m3c.json)。

## 作用域数值顺序与复用

`LowerSync` 现在可将具备原始区域树的常量嵌套令牌程序送入共享的数值顺序服务及
原有物理分配/发射器。该路径不重新提取存储冲突或最小需求。

证明子图只包含在所属命名循环层级中始终活动的体内边和相邻原始循环体接缝。
祖先域必须完整；固定内部后缀坐标在计数器复位后仍保持原意。仅首次、末次或
其他裁剪域的边仍保留为实际交接义务，但不扩张为统一复用证据。查询成功证明
实际顺序；失败仅表示当前子图无法证明，而非实际程序不存在该顺序。

每次组合保留原生启动/启动、完成/完成链接以及所有跨越端口。二进制重复始终
在相邻原始循环体间平移接缝。缓存归属于不可变的体/接缝所有者，并包含次数和
所需相对端口；相同大小的不同复位体不能误用彼此的证据。累加器访问保护不被
转换为完成到启动的事件边。

每种混合基数进位类别通过一个代表查询证明相邻交接的消费先于再次发布。
证明路径中的边在相应命名层级上统一，且参考顺序向前的路径不能离开连续子区
后返回，因此代表路径可平移到该类别的所有成员。裁剪交接也可利用这种统一
子图证据；它本身无需作为证明边。相同流水线屏障仍独立检查完整载荷调度中的
直接原生前驱。证明失败保留拒绝，不宣称物理容量不足。

所有实际交接（包括重复使用和例外边）进入未更改的分配器；不删除命令来满足
容量或证明限制。所有者覆盖分配和发射阶段，查询回调借用其生命周期。默认
开关保持关闭；显式启用 `RealizeSync` 时使用实际令牌路径。

数值摘要深度随次数的对数增长。B 个具体外部端口沿 `O(B log K)` 路径传播；
符号交接族不展开为 K 个端口。行组合、端口集合复制/比较、坐标路径和叶查询
成本分别计入。计数器记录不同的非空摘要节点和行条目，不重复计算缓存别名，
也不等同于全部内存字节数。

独立有限检查覆盖证明子图的四类事件查询、对实际 SSA 顺序的包含关系、所有
接受的复用/屏障证书，以及实际物理命令的匹配、因果复用和六 ID 合规性。
序列化和 C++ 生成另行验证。扩大到 1,048,575 行或访问时仍为三个 SET、三个
WAIT 和 24–26 个算术站点。单次时间仅为描述性数据，未进行设备验证。
[记录](https://github.com/tonibohnlein/pypto/blob/365b803a45072f1c00e8eca5da9942bd9828685f/docs/en/dev/ir/token-pipeline-m3d.json) 保留范围与限制。

DMA 同流水线机制、非统一动态原始循环界限、一般非矩形条件及缺失的调用者/块范围证据
仍有明确限制。驻留缓冲区复位和零内层程序不会为通过物理阶段而删除逻辑顺序。

## 调用者证据与动态单次框架

两个阶段通过既有封闭 call/submit 图收集参数范围和完整逻辑块索引包络。
统一作用域要求整个包络支持同一表示。依赖逻辑块且跨越活动边界的包络通过
下述解析式分区处理；其他变化域仍拒绝。导入器证明动态起点在调用中不变且统一执行零次或一次后，
作用域令牌保留原始起点表达式和序号零，不把数值占位起点当作执行坐标。
零次子树无需导出未访问的后代框架；任何可达缺失框架仍拒绝。动态框架上的
任意比较守卫仍不可用，平坦循环传输仍要求常量边界。

重新收集范围只证明坐标有效，不证明任意程序编辑后的需求覆盖。例如修改
调用者使原先未执行的主体变为活动，可能使原有令牌协议不再覆盖需求。
LowerSync 解释实际协议而不重建遗漏需求；修改负载、控制或访问的变换须保持
或重新建立同步。物理所有权属性仅认证提供的协议，包括手工修改的令牌使用。

证据收集每阶段一次，完整流程两次，分别计入既有缓存失效和调用图工作。
不枚举访问次数或调用者取值，不声称全局每表达式只访问一次。原始 PyPTO-lib
matmul/GEMM、动态零/一次框架、调用者修改拒绝和修改后的令牌均有独立有界检查。
下述调用激活分区进一步扩展这一统一包络支持。

## 调用激活分区

既有解析式激活分区现在独立于需求分析共享，提供穷尽、互斥且原始类型算术
已验证的逻辑块区间。插入逐区间认证，将源身份索引的令牌切点及循环携带状态
合并到同一原始负载树。同一负载宏的记录共享完成事实，各情况携带变量独立；
所有等待（包括同管线等待）带精确调用守卫。记录及纯状态更新本身不增加顺序。

未使用的状态也必须在整个调用域中有定义：记录位于原始完整负载宏后，携带值
从 completed 开始，零次结果保持 completed；捕获只比较原始常量坐标，动态单次
框架保留原始起点。不把记录移入单独初始化分支，不重放跳过的负载或假设历史。

降低只为恢复负载和原生契约而剥离令牌，然后重建激活域并解释实际 SSA 使用。
只接纳在完整区间上恒真或恒假的原始支配块变量比较。修改后非统一的守卫明确
拒绝，名称或插入元数据不提供语义。非活动等待不生成物理族，重复使用仍独立。

每个情况通过既有分配器及独立坐标所有者认证；共享切点发射将端点算术和命令
一起置于互斥守卫内。调色板共享限定于同一调用，仍要求原有入口/出口契约。
任一情况失败则整体拒绝。原生规则、分配算法及默认关闭策略保持原状。

C 个情况、N 个原始语句和总令牌状态 T 的遍历输入成本为 `O(C(N+T))`，T 本身可随
C 增长；框架深度、守卫域、顺序摘要、负载限定和分配成本另计。诊断记录解析器 Read 访问次数、等待、非活动等待和输出族数。不展开访问次数，不声称通用激活的常数成本。
原生返回完成及设备正确性仍需独立验证。

诊断中的 Read 次数不包含嵌套等待专用遍历，其等待叶节点单独计数。非活动等待
仅指调用情况守卫为假的等待，不包括零次主体或空循环坐标域。

## 生产迁移完成范围

可选 `realize_sync()` 已成为三个共享服务的事务编排：逻辑插入、验证和实际令牌
物理降低。默认开关仍关闭。缺少导出或物理证明时保留原始函数并委托 PTOAS，
不调用旧的直接数学物理化旁路。已有令牌和已拥有物理计划在任何委托前拒绝。
事务内部插入不改变调用者、标量和控制，因此可共享本次收集的证据；独立
`LowerSync` 仍重新收集当前输入证据。
插入生成的逻辑 IR 若未通过验证，则作为内部编译器错误传播，不转为委托原因；
独立降低中的非法用户令牌仍报告输入验证错误。

旧直接路径只保留显式审计入口。资格测量脚本使用该审计接口作为基线，避免将新
生产路径与自身比较。该迁移不
证明原生调用返回语义、设备性能或任意符号嵌套能力。

## 完美嵌套与原始坐标帧

令牌插入、负载重新导入和数学检查使用相同的原始坐标帧导入器。
嵌套循环保留结构化源树；有限及常量单循环输入继续使用现有叶子路径。
旧的完美嵌套压平选项已删除，因此检查接口直接验证生产表示。
调用情况导入遵循同一契约，不放宽访问、控制或初始化前提。

原始循环身份、非零起点、非单位步长、零访问和计数器重置保持不变。数值接口构造
可能比压平周期表示更昂贵；不承诺任意嵌套旋转槽或符号次数。嵌套 DMA 回归随次数
增长保留七个族和至多五个轴，单元素区间可省略轴。这是该输入族的测量界，不是
数值接口的统一线性界。

## 调用出口完成

内部令牌或物理匹配证明本身不建立调用完成。公开 `LowerSync` 与 `RealizeSync`
取得整核所有权时，在返回前插入既有 A2/A3 `system.bar_all`，按照该原语的契约
完成最后的异步载荷。子区域降低仍保留待完成载荷。主机有界检查不替代原生设备验证；
两个编译器的性能比较必须采用相同的终端完成策略。

## 闭合的当前前缀事务

实际令牌降低支持结构化的闭合当前前缀服务，包括等待后的发布及空源前缀。
源流水线 `p` 到目标 `q` 的一个服务按顺序执行
`record(p), wait(q), record(q), wait(p)`，每个等待引用对应记录。
确认顺序已在输入逻辑程序中表达，分配不会暗中增加反向前提。
连续的同流水线记录/等待使用已有完成原语或合格的标量原生顺序规则，不插入标量屏障。

结构语法要求同一控制路径上的匹配，令牌不能逃逸。序列、分支和顺序循环组合闭合
事务，支持零次访问、跳过分支及计数器重置。进展和角色重置来自结构证明，而非次数
展开或存储覆盖。每个使用方向通过已有资格、原生占用及保留检查取得最多两个角色。
其他形式保留已有替代降低或明确拒绝；这不是通用结构化令牌支持。

公开插入 Pass 可消费显式提供的保留子区域：

```python
with passes.PassContext([], autosync_disjoint_gm=True):
    children = passes.prepare_native_sync_children(original_function, [original_loop])
with passes.PassContext([], autosync_policy="conservative_prefix"):
    logical = passes.insert_sync(accepted_children=children)(original_program)
    optimized = passes.optimize_sync()(logical)
    physical = passes.lower_sync()(optimized)
```

`prepare_native_sync_children` 对整个原始、已放置的 Buffer 函数执行一次既有精确
分析，再导出显式请求的循环作用域。它使用当前上下文的目标与显式 disjoint-GM
前提；不会分离子区域重新分析或自动搜索候选。整个根函数或任一导出不受支持时，
在返回能力列表前拒绝。空作用域列表跳过分析且不导出任何证明。
不可变的 `passes.NativeSyncChild` 共享并保留原始数学所有者，没有公开构造器。
首个家族只含原生内部计划、本地效果且事件调色板为空。根分析使用的 disjoint-GM
前提不会传给保守父区域；导出仍拒绝外部存储效果与调用方／启动范围特化前提。
能力绑定原始所有者、作用域、目标、保护和坐标；克隆、
未提供调用方前提以及重叠请求都事务性拒绝。父区域入口服务保留出口可能未完成的
访问效果；通知闭合不代表载荷完成。零次子区域访问仍可能支付入口服务成本。
传输组合和 JIT 自动发现仍不可用。此导入既不要求也不伪造
精确存储选择器。

### 显式带事件区域子计划

`prepare_eventful_sync_children(original_function, [original_loop])` 在原始词法上下文
中构造一次限定区域分析。`insert_sync(eventful_children=children)` 仅在显式
`conservative_prefix` 策略下消费能力；随后通过现有 `OptimizeSync`、`LowerSync`
管线降低。能力保留原始所有者、作用域、祖先语句及区域数学分析的绑定所有者。
原始支配的无信号描述符保留物理根别名。首个家族拒绝外部存储效果、原生事件占用、
自由外层坐标及未供应调用方数值，包括形状和有效范围引用的值；不选择代表性零值。
保留原始循环/载荷坐标、外层保护与计数器重置。失败批次不发布部分能力、命令或资源。

父区域分别跟踪尚未完成的载荷访问和有方向的事件资源。每个保留的子区域报告其协议可能
使用的事件方向，包括为闭合循环而生成的反向确认，以及原生操作预留的事件。即使两个
子区域使用不同的缓冲区，也可能复用同一方向的事件 ID。如果前一子区域可以到达当前
入口，且两者都使用 `p -> q`，父区域就建立从 `q` 到 `p` 的交接，使先前在 `q` 上
消费事件的 WAIT 先于随后在 `p` 上发布事件的 SET。互斥分支可以使用同一方向，
无需在两个分支之间交接。

`LowerSync` 检查传入的 token 程序，包括反序列化的程序。它先按方向为父区域预留
ID，再用剩余 ID 降低每个子区域。在子区域的原始入口，它检查交接是否覆盖子区域实际
发布事件的方向和原生操作预留的方向。用作证据的 record 只捕获执行到该 record 时的
流水线前缀。缺少顺序证据或可用事件 ID 时，验证失败。

每批请求使用 `ParentStmtAnalysis` 构造一次原始所有者语句/定义索引；每个区域仅访问
自身作用域、祖先和必要的支配绑定。`child.describe()` 报告批次共享索引节点数
（每批只计一次）、单查询作用域节点数及捕获定义数，不运行识别或构造导出。独立批次
构造各自的索引，不展开循环次数。这不代表一般符号帧、带事件通信
或整个 Qwen 的覆盖。

## 显式整模块同步所有权

`LowerSync(require_whole_module=True)` 和 `RealizeSync(require_whole_module=True)`
原子请求所给 Program 内所有本地 AIC/AIV Buffer 函数的同步所有权。默认仍保留有
标志命令的逐叶所有权和委托。未知 helper、外部或 SIMT 执行域会拒绝整个请求。
即使没有逻辑同步操作，也验证实际操作和原生资源，不能用伪标志命令表示所有权。
存在未完成载荷或命令时保留调用末尾 drain；真正空返回没有异步义务，无需 drain。

LowerSync 保持实际 token 程序，不能据此声称手写 token 已覆盖所有内存冲突；后者
是 InsertSync 的独立保证。RealizeSync 还需证明所选精确或保守模型的依赖覆盖。
成功的显式请求发布保留属性 `autosync_whole_module`。后端检查实际代码生成单元的
全部函数、peer 和生成 helper，仅在合格 A2/A3 目标上保持原物理放置、且全部已限定的单元才能对 PTOAS 使用
`--enable-insert-sync=false`。显式请求遇到未知域时拒绝，不静默委托更改方案。
原有仅标志所有权部署仍启用下游插入，由 PTOAS 识别已有标志。

生成的 PTO 包含首行所有权标记，配套 `<unit>.sync.json` 记录 SHA256、全部域及
限定的编译参数；组模块的 raw 导出同样将 manifest 放在实际 PTO 文件旁。
调试重建验证字节哈希并恢复参数。修改过的 owned PTO、缺少 manifest 或不支持的
参数都要求从 IR 重新编译。该格式检测意外文件不匹配，不是认证机制。
独立 PTOAS CLI 不读取 PyPTO manifest，使用其默认选项编译 raw owned PTO 不在
此所有权合同内。

`test_whole_module_sync_ownership.py` 验证空方案、仅 barrier、最终 store、混合
helper 拒绝、逐模块参数、组 raw 文件、序列化及调试重建拒绝。全部为主机模型检查，
不证明原生缓存可见性或设备执行。
