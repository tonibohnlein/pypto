# RealizeSync（实验性）

插入生成的逻辑令牌若未通过验证，则报告内部编译器错误（internal compiler error），
不会转为 PTOAS 委托；独立 `LowerSync` 的非法用户令牌仍报告输入验证错误。

此可选 Pass 在存储降低之后尝试由 PyPTO 规划同步。默认编译仍将同步交给 PTOAS。

```python
from pypto import passes

# Explicit caller promise: distinct GM arguments denote disjoint allocations.
with passes.PassContext([], enable_pypto_autosync=True,
                        autosync_disjoint_gm=True):
    compiled = kernel.compile(a, b, c, config=config)

# Turn PyPTO's pass off; PTOAS still handles synchronization.
with passes.PassContext([], enable_pypto_autosync=False):
    baseline = kernel.compile(a, b, c, config=config)
```

PyPTO 仅对已完成物理地址分配的 Buffer IR、已限定的 AIC 矩阵乘与 AIV Vec 片段和
manual a2a3 宏变体调用现有访问导入器、紧凑最小需求分析与物理实现。
如果地址分配、GM 不相交、目标、访问、控制、端点或资源证明不满足要求，
将**原始内核主体**留给 PTOAS。这不保证 PTOAS 支持所有输入；下游错误仍会传播。
内部编译器错误不会转换为回退。保留分析结果的研究 API 仍严格报告资格失败。

成功尝试会发布完整主体和布尔属性 `pypto_autosync=True`。采用逐函数所有权时，
编译器启用 PTOAS 同步插入。PTOAS 逐个跳过含显式 SET/WAIT 或 record/wait
事件的函数，仍可在同一模块的其他函数中插入同步。PTOAS 的跳过规则要求标志事件，
所以仅含屏障或没有命令的候选会将原始主体委托给 PTOAS。该路线上的用户已有同步也
遵循同一规则。

在 A2/A3 上由 PyPTO 分配物理地址并使用 `autosync_policy="conservative_prefix"`
时，PyPTO 也可联合规划满足条件的 AIC/AIV 对端单元。受管理的 GM FIFO 路线保留
原生传输，并在 Buffer IR 中或通过符合条件的 Functional IR 借用验证本地就绪和
释放顺序。用户编写的 GM 通信路线要求两端均采用 Buffer IR，保留原有通信，并验证
本地同步及共享 GM 的可见性。任一端不满足要求时，两端交给同一次 PTOAS
调用。精确策略采用逐函数路线。独立 Pass 还可通过 `require_whole_module=True`
要求所有本地 Buffer 域均取得所有权。

当 FIFO 端点包含条件执行的工作，且工作循环之间有用户编写的硬件 MIX
`syncall` 时，结构化规划器会检查该位置的所有 FIFO 借用均已结束。
同步调用保留在原处，规划器继续跟踪尚待完成的本地读写。下次接收从环形缓冲区的当前位置继续。

取得整个单元的所有权要求每个生成的域（包括链接的对端）均具有完整所有权，并且
没有生成的辅助函数。通过验证的空计划和仅含屏障的计划可以参与。后端对照生成的
PTO 验证 `ptoas/<unit>.sync.json`，然后使用 `--enable-insert-sync=false`
编译该单元。使用识别所有权的构建流程重编译时，应将 PTO 与清单一并保留。
编辑生成的 PTO 后，需要重新编译 IR 以建立所有权。

启用后，`report/autosync.json` 记录各尝试内核选择的规划路线（`pypto` 或
`ptoas`）及原因。单元清单记录下游同步插入策略。外部源码、内置模板和运行时绑定
函数保留外部所有权，并从规划报告中省略。请保留已取得所有权的 IR 主体及编译器
生成的属性。对已取得所有权的计划再次运行此 Pass 会拒绝。

开关与不相交契约属于 JIT 缓存标识；转储和性能分析上下文保留它们。
`PassManager` 构造后不能更改二者。分配算法不变；此接口不提供不安全的无同步模式。

限定的[物理构造](../ir/15-physical-demand-realization.md)建立模型载荷顺序、
匹配和合法方向复用，假定调用入口通知状态为空并关闭通知。公开的 `RealizeSync`
和 `LowerSync` 在取得整核所有权时还会在返回前插入 A2/A3 `system.bar_all`，替代
被跳过的 PTOAS 终端完成操作。通知关闭本身不等于载荷完成。不支持的出口事务性拒绝。
内部子区域降低仍可返回待完成载荷，不插入子区域出口屏障。原生指令和运行时行为仍须
单独设备验证；性能比较必须采用相同的调用边界策略。

调用范围恢复通过现有算术分析器保留已经验证的 SSA 定义和作用域内整数比较，
因此能够利用共享操作数证明关联表达式的数值边界。每个原始中间结果必须先通过
机器位宽检查；代数抵消不能修复此前的溢出。分支局部证据不逃逸到其他分支，
任何未通过验证的调用方都会使合并后的形参边界保持未证明。导出结果仍是数值区间，
并非通用的关系形状契约。

## 显式保守前缀策略

默认策略仍为 `autosync_policy="exact"`。可显式请求只依赖已验证操作效果、
而不要求精确出现次数或 GM 选择器的路线：

```python
with passes.PassContext([], enable_pypto_autosync=True,
                        autosync_policy="conservative_prefix"):
    compiled = kernel.compile(a, b, c, config=config)
```

此路线使用完整内存空间的读写包围集：不同 GM 根可能重叠，本地槽位及视图共享其
物理内存空间类别。原程序的访问有效性前提不变。分支合并可能访问，循环保留零次
执行及回边事实，不展开访问次数；可能写不会清除旧义务。不支持的效果、标量内存
就绪性和复合传输仍事务性拒绝。

通常，消费者等待源流水线在当前位置之前的所有操作完成。如果源流水线在最后一次访问该存储后
又执行了无关操作，这种等待就会延迟存储复用。在单个顺序循环中，保守规划器可以在最后一次
相关访问之后立即记录完成状态，并让处于空闲状态的目标流水线在该处等待。规划器根据操作的
物理读写范围和控制路径选择位置，重新检查循环入口、分支和回边上的不动点，并验证新交接
能够替代原等待而无需增加其他前置服务。验证失败时保留原位置。物理降低负责分配事件，
并在事件复用需要时补上反向确认。

对于满足条件的导入对端，记录可以放在来源流水线上连续且独立的操作之前，等待仍留在
消费操作处。完成状态分析会恢复后续仍需等待这些操作的同步。对于满足条件的首次迭代，
循环可以在入口根据已就绪的值构造条件，获取循环前的完成前缀。重放时，首次等待不计入
推迟捕获的操作效果，后续迭代仍执行原有同步。用户编写的对端命令保留原位置，使用原生
事件资源的操作会截断候选序列。如果无法为拆分后的同步分配事件，则保留原调度。

对导入端点完成事件分配后，规划器可将本地 SET 提前到前一分支的两个分支体中，或移到
前一次循环迭代的末尾。分支体中的 SET 使用接收分支的条件。对于步长为一的循环，仅当
下一次迭代会执行受条件保护的接收操作时才发出 SET。两种形式都保留 WAIT 的位置和
物理事件 ID。规划器检查移过的命令是否影响事件复用，并从提前捕获的前缀中排除移过的
载荷效果，再验证所有已选服务。如果任一检查或 Buffer 有效性验证失败，端点使用原分配。

覆盖存储时，也可以提前发布最后一次读取相应槽位的流水线的完成信息。如果一次等待保护多个
槽位，则记录必须位于这些槽位的最后一个相关读者之后。规划器根据原有控制流检查记录处已知的
完成信息能否满足后续需求，并检查事件复用。只有在原有标志预算内且能保持等待位置时，才采用
提前发布的方案。

同一个等待可能会约束相互独立的操作数。例如，左矩阵搬运依赖较早的查询加载，而右矩阵搬运
依赖较晚的页加载。规划器可保留页加载的原发布，用空闲的定向事件向第一次搬运交付较早的
前缀，再将页加载的等待推迟到第二次搬运之前。它会检查物理字节重叠、原生资源预留、中间
命令以及确保事件先消费再发布的反向交接。对于较长的消费者序列，保守数据流也可选择提前
捕获，并在后续消费者首次需要时恢复其余同步。

对于单核上已验证的工作循环，编译器可简化具有常量边界的小型子循环内的同步条件。它在原始
迭代坐标上求值，将循环切分为两个连续区间，或将相邻两次迭代编为一组。候选方案需减少控制
开销，且满足本地调度共用的每函数代码增长预算。编译器计入新增载荷位置及替换后整个控制树。负载、本地命令和用户编写的 FIFO 操作均保持原执行顺序。

在结构化端点的同一位置，多个自动生成的 SET/WAIT 对可以向同一条本地流水线传递完成信息。
例如，若第三条流水线已等待两个生产者，它可用一个事件对传递两者的完成信息。规划器比较
原事件组、其较小子集和单条中继路径。仅当各流水线后续发射及观察已完成命令的屏障所见的
负载完成关系都相同，并且先前的事件消费仍先于复用时，才采用命令更少的方案。新增中继需要
可用的定向事件 ID；在循环中，还需由保留的命令在下次迭代前将消费信息传回发布流水线。
这些检查沿用原有控制流，无需新增条件判断。如果中继还会传递无关负载的完成信息，规划器
保留原事件组作为候选。

两个先后执行的保留子循环可以通过已有事件传递完成信息。对控制流已知且规模有界的调用，
规划器根据完整的物理调度重放第二个子循环入口处生成的事件对和局部屏障。只有当每个载荷
发射时各流水线已完成的前缀相同、每次事件复用前上一次等待都已消费事件，且退出时所有事件
都已消费，才可以删除事件对或屏障。遇到未知分支、不透明的原生效果或超出重放预算时，
规划器保留原有的交接指令。

循环可能复用序言访问过的存储。第一次覆盖可能需要等待循环前的读取完成，而后续覆盖
需要等待上一次迭代的读取完成。对于满足条件的最内层顺序计数循环，如果其第一个负载操作
无条件执行，规划器会分别分析首次迭代和回边上的不动点。位于分支或外层循环内的循环也
适用。例如，归约循环可在入口等待上一行的写回完成，只要后续迭代无需等待写回流水线上的
其他操作，就可以在迭代间保留该完成状态。对于嵌套循环或含多个循环的函数，规划器只移动
循环内不执行负载且仅入口需要的同步。其余同步保留原位置，以便继续确认事件复用。对于
单一顶层循环，仅回边需要的同步还可以从第二次迭代开始在原位置执行。如果能证明回边来源
流水线在该循环入口为空，也可以让这次等待
每次都执行。首次等待只捕获空前缀，循环中的事件对可用于确认事件复用，从而省去单独
的反向确认。两种分析都检查实际存储范围的重叠，包括别名。循环中的
条件访问因此可能在后续迭代中重新产生依赖。生成的循环保留原边界及负载主体。

调用排空及整核所有权规则不变。
此策略不会在精确结果导出失败后悄悄替换成功数学结果，其标识由上下文复制、JIT
缓存和路线报告保留。

## 有限 Vec 覆盖

AIV 路径复用现有需求分析、插入位置和标志分配器，支持静态、完整有效的二维 Vec
load/store，以及共享 Buffer 配方目录中的逐元素操作。常量标量操作数可用；任意标量
生产计算仍不被接纳。共享 Buffer 验证器检查各指令的原地别名契约。

同一路径支持共享的 `row_max`、`row_sum`、`row_expand_sub` 和 `row_expand_div`
配方以及完整有效的连续列向量。归约读取源，写入目标及覆盖整个已声明 scratch
缓冲区的保守范围；广播读取两个输入。最小需求与选择器针对这些建模效果，不声称
精确恢复原生 scratch 字节访问。现有验证器拒绝非法 scratch 重叠，资源目录在分配前
保留原生 V/S 事件 ID。一般列主序矩阵和部分有效描述符仍不支持。

原始 `examples/intermediate/02_softmax.py` 现可选择 PyPTO autosync 并通过 PTOAS
生成 C++。主机检查覆盖建模访问、covers、查询、选择器、匹配、物理复用，以及具有
scratch 复用和计数器重置的小型重复流水线。测试循环次数从 4 增至 1,000,000 时，
保留表示大小不变。原始 RMSNorm 和 LayerNorm 示例仍委托给 PTOAS：其完整函数尚未
被选为 Buffer IR。这是更早的降低边界，而非 autosync 分配失败。新增案例尚无设备验证。

已分配的 Vec 根与静态 subview 使用统一物理字节域。嵌套 subview 保留原始行距；
连续 reshape 保持字节范围。不同 SSA 名称或元素宽度不会使重叠分配变得不相交。
连续访问用一个区间，非连续窗口每物理行用一个区间；成本取决于静态窗口行数而非
循环次数。分区按写矩形的行事件扫描，只用当前行带内有效的写边界切分列，仍覆盖空洞和只读域。
共享行/列索引只访问与完整仿射访问包围范围相交的类，再验证精确的访问成员关系。
W 个写矩形和 C 个输出类的分区成本为 `O(W log W + C)`；一般重叠矩形仍可能
产生二次规模的 C。`class_tests` 统计成员关系检查，`class_lookup_tests` 单独统计二分查找比较。重复区域仍须满足
现有成员关系与每次访问刷新条件。

对于满足条件的旋转槽分配，共享足迹解析器分别记录槽选择器和槽内矩形。例如，外层迭代
可以通过 `outer % 2` 选槽，内层迭代则读取从 `inner * 16` 开始的列。精确导入保留
两层迭代坐标。保守数据流记录槽访问历史，并用一个矩阵范围覆盖各次内层访问。当对端接收
无法确定槽时，可能访问的字节覆盖整个环形缓冲区，接收操作不提供整环的确定覆盖。

Mat 提取和 Acc 到 Mat 的插入使用相同的规范矩形。依赖分析前，转置的 Mat 视图将
偏移和范围映射回分配的坐标轴。精确导入仍检查各传输原有的原生对齐要求，并分别保留
旋转槽选择与插入的槽内偏移。

当不同布局或范围的已分配 Mat 描述符重叠时，保守数据流沿物理字节边界划分区域。
整块加载参与它覆盖的每个区域。即使一个整块加载覆盖提取和插入的访问范围，只要两者
可能访问的字节不相交，它们仍可并行执行。这些区域记录所有迭代中可能发生的读写，
移动写入和部分写入保留先前的访问历史。布局不受支持或物理字节区间过多时，沿用较粗的
包围范围。

动态 valid 更新、运行时窗口偏移、未经证明的槽选择和非连续 reshape 仍需各自的导入与就绪
证明。GM 视图与步长仍遵循现有导入器、发射器契约，不把有间隔的
GM 视图当作连续视图，也不从 SSA 身份推导不相交。静态局部视图不代表一般动态元数据支持。

同 MTE2 需求可以有正确的最小需求分析，但没有已限定的局部屏障机制，此时明确拒绝
可执行导出。研究物理结果的 `native_reserved_ids` 单独列出原生宏固定事件占用；
分配器从相应 AIC/AIV 方向池排除这些占用，分配算法与资源容量不变。

主机回归覆盖原始加法/乘法示例、重叠分配、嵌套行距、原地操作、零次与重复访问，
独立检查字节访问、实际 covers、四种事件查询、边界选择及因果复用。PTOAS C++ 生成
单独检查，不代表新增设备验证。

## 原生累加器保护与标量屏障

在命名的 manual `a2a3` 目标契约下，对同一物理 L0C 累加器的连续 Mmad 操作，若
`floor(M/16) * floor(N/16) >= 10`，可省略其存储同步。导入器检查完整有效形状、
Left/Right/Acc 操作数与 `[1, 4095]` 范围内的匹配维度，实现
[Mmad 同步优化](https://asc.gitcode.com/api/SIMD-API/basic_api/cube_compute_ISASI/mmad_compute/Mmad.html)。
这不是整个矩阵流水或 FIX 流水的豁免。

物理访问和边界选择器保持不变。提供者证书仅在有限归约与跨区域归约前过滤受保护的
存储见证，不过滤显式先决条件。稀疏计数器证明中间的矩阵操作都在同一累加器上满足
条件，且没有其他访问触及该累加器；通过循环次数计算而不展开迭代。FIX 读取会中断
保护。重新初始化不接受入向保护；同址同布局别名共享物理身份。此规则不会添加
completion-before-start 事件边。原有前沿扫描仍有效：原生启动顺序沿受保护写入链
传递入向义务，原生完成顺序将出向义务传递到后续消费者；只读访问的 WAR 义务仍明确保留。

支持首个矩阵位置的初始化/累加选择。位于其他矩阵操作之后的条件初始化仍采用保守
处理，因为其仅启动阶段有效的需求需要更丰富的族活动契约。未知目标不获得豁免；
物理降低拒绝与保留分析契约不一致的目标。最小需求与顺序相等的声明针对所选硬件及
效果契约，不代表利用了全部原生优化。

禁止 `PIPE_S` 屏障；物理资格检查与发射仅允许 M/V 局部屏障。数值服务可使用显式
提供的标量原生顺序边，但仍保留跨流水就绪义务。标量载荷导入尚不支持，因此继续
委托处理，而不是构造虚假的标量屏障。
[PipeBarrier 规范](https://www.hiascend.com/doc_center/source/zh/canncommercial/900/API/ascendcopapi/atlasascendc_api_07_0271.html)
说明标量同步由硬件保证，标量屏障会引发硬件错误。主机回归验证这些契约下的图性质，
不代表新增设备验证。

## 索引 Buffer 契约

显式启用的导入器复用 `buffer.gather` 和 `buffer.scatter` 配方，只接受已放置、
完整有效且稠密的 AIV 缓冲区。索引必须是目标局部缓冲区内有效的物理元素偏移；
这是操作的调用方契约，并非静态范围证明，也不支持任意指针。
Gather 的源读取与 scratch 写入使用整个缓冲区的保守包络。
Scatter 先清空整个目标，因此在共享操作契约下目标写入是精确的。
保留诊断逐访问标注 `exact` 或 `enclosure`；最小需求和边界选择器描述所选模型。
保守模型的 covers 不一定是具体执行的最小 covers，但其闭包覆盖具体访问冲突。

现有原生资源目录保留手动模式 V/S 辅助标志，分配算法及 PTOAS 委派保持不变。
缺少放置、部分有效范围或非法写别名仍以事务方式拒绝。
PR #3333 的带填充行主序归约结果尚不满足此完整有效 Buffer 契约；
集成该 API 不会把填充区域静默视为有效数据。

## 就绪的调用坐标

Pass 在分析内核之前从编译程序的直接 Call/Submit 调用点收集有界整数坐标，
合并所有调用点，保留原始形参位置，对未知范围保持未证明。导入器支持各 GM 域的
共同参数平移，并检查算术和分配边界；数值分析不会特化为单个 tile 偏移。
存储查询需要对应的原始坐标绑定。
参见[参数化 prefill 合同和检查点](https://github.com/tonibohnlein/pypto/blob/365b803a45072f1c00e8eca5da9942bd9828685f/docs/zh/dev/ir/16-parameterized-prefill-checkpoint.md)。
显式有界 INDEX 形参可表示 GM 动态首维；访问必须位于最小允许尺寸内，选择器
要求实际尺寸。原始位宽算术及转换需要非负且保持值的证明。

效果不变的常量完美循环巢保留原始框架，以经过检查的混合进制序号发射物理命令。
该特化不包含移动切片和累加器重置分支。下述合格嵌套投影构造在调用、访问和作用域
端点证据齐备时扩展此基线；任意符号嵌套及嵌套逻辑 token 导出仍不可用。

## 参数化嵌套投影

配置后的 Qwen output 与合并 gate/up 使用同一 opt-in pass。闭合程序的调用与 launch
证据限定就绪不变坐标；数值区域组合保留 resident 操作数、累加器初始化和计数器重置。
所有活动 case 均合格后才向原始负载主体插入守卫命令。如果各启动情形的差异只涉及原始符号起点循环的迭代次数，
且能证明每个情形中选出的物理命令及其顺序相同，降低过程可直接测试是否为首轮、末轮，以及是否有上一轮或下一轮。
六 ID 分配使用现有充分证书；
不支持的坐标、同管线机制或资源证据仍委托。

物理降低可在已分配事件的端点边界处，将合格的最内层循环拆分成最多三个常量边界阶段。
迭代次数少于四次时，只有每个阶段恰好包含一次迭代的循环才符合条件。
每个阶段按原顺序执行原始迭代，并在原始负载间隙发出相同的已分配命令。
选择时会计入外层循环遗留的条件和新增的循环控制。在每个启动情形中，特化后控制开销的上界
必须低于原有带条件降低的开销下界。编译器按内核累计复制的负载位置和展开后的替换代码大小，
在超出预算时保留带条件的实现。此优化不展开启动情形或周期余数。

在两个相邻的载荷操作之间，如果两个同步决策使用相同的槽位或循环条件，调度器可以只判断一次。它可以把中间的一条核内同步指令复制到两个互斥分支中。每条执行路径仍在原位置执行该指令，并保留全部载荷操作和事件编号。

详见[流水线检查点](https://github.com/tonibohnlein/pypto/blob/365b803a45072f1c00e8eca5da9942bd9828685f/docs/zh/dev/ir/18-qwen-prefill-pipeline.md)的前提、独立检查及选择限制。
不代表任意符号嵌套、完整 prefill 模型、原生调用完成或设备行为已获验证。

## 逻辑令牌生产路径

可选 `RealizeSync` 现在调用与独立阶段相同的 `InsertSync`、逻辑验证
（当前 `OptimizeSync`）和读取实际令牌的 `LowerSync` 服务。
旧的数学结果直接物理化接口仅用于显式审计；令牌导出失败不会绕过令牌路径。
失败事务保留原始未同步函数，不发布中间令牌。已有逻辑令牌或已拥有物理计划在
所有委托出口前拒绝；已有令牌应调用独立 `LowerSync`。

事务只收集一次调用者证据，因为插入保持调用图、签名、标量定义和负载控制。
独立 `LowerSync` 仍从当前（包括反序列化后的）Program 重新建立证据。
默认开关、PTOAS 委托、空/仅屏障计划策略、资源分配和硬件规则均不改变。
合格嵌套令牌支持见 [逻辑流水线](60-logical_sync_pipeline.md)，不承诺任意符号嵌套。
